DDL 跨库同步
业务库 ↔ 历史库 · 功能图说

解决"业务库 DDL 变更容易遗漏同步到历史库"的痛点 — DBA 配库对白名单，Archery 自动判断 + 自动建历史库 DDL 工单，业务 RD 啥都不用管。

01

痛点 — 业务库 DDL 容易漏同步到历史库

业务库跟历史库通过时间戳同步数据，但 DDL 不自动同步。漏了 ADD COLUMN 同步就直接断。

现状 · 漏同步场景

业务库 ADD COLUMN card_serial ✓
历史库 Unknown column 'card_serial' ✗
同步任务 crash / 数据丢失

业务 RD 改完 DDL 跑完没异常，但 时间戳同步任务跑历史库直接挂，要 DBA 手动补 ALTER。

→

DDL 跨库同步后

业务库 ADD COLUMN card_serial ✓
Archery 识别表进白名单 →
历史库 自动建 DDL 工单 → 执行成功 ✓
同步任务 继续跑通

业务 RD 跟以前一样提单，历史库工单自动生成，走同一审批人审批。

漏同步的 7 种 DDL 各自怎么算

DDL 类型 历史库是否要同步 漏同步后果
ADD COLUMN 必须 时间戳同步跑历史库报 Unknown column，同步断
MODIFY COLUMN（改类型/长度） 必须 同步超长字段报错 / 类型转换报错
CHANGE COLUMN（重命名+改类型） 必须 历史库字段对不上，同步逻辑出错
RENAME TABLE 必须 同步任务找不到原表
DROP COLUMN 可选 历史数据保留，后续清理时再同步
ADD INDEX / DROP INDEX 通常不用 历史库数据少，索引意义不大
02

核心思路 — 8/21 拍板

历史库只同步部分表（不是全量），业务 RD 不知道"要不要同步"。解法：DBA 配库对白名单，Archery 自动判断。

v0.4.5 智能回滚

历史库 DDL 工单也走智能回滚 (ADD COLUMN 逆向 DROP COLUMN)，失败能自动回。

v0.3.0 gh-ost

历史库 DDL 大表检测走同一阈值，超过自动套 gh-ost 避免锁表。

v0.3.x 大表防呆

历史库 DDL 提单时也走大表防呆 (大表 → 提示 gh-ost / 立即执行 / 终止)。

v0.2.0 钉钉 OA + audit_drivers

历史库 DDL 工单审批人跟业务库一样，审批消息推钉钉，DBA 不用切系统。
