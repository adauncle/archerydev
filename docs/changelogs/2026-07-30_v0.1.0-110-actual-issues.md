## 10 个事故（按发现时间排）

每条都包含：**问题 → 报错/现场 → 根因 → 解决 → 防止重演**。

### R-1 · 外网域名 `prodArchery.ahggwl.com` 报 400
- **报错**：浏览器访问外网域名 → HTTP 400
- **根因**：v1.10.0 docker 容器内 `ALLOWED_HOSTS` 含外网域名，升级到 host 进程后 `.env` 只配了 `172.20.2.110 + localhost`
- **解决**：`.env` `ALLOWED_HOSTS=172.20.2.110,localhost,ProdArchery.ahggwl.com,*.ahggwl.com`
- **防重演**：changelog 注明 ALLOWED_HOSTS 默认值需含外网域名
- **MR**：MR 1 配套 `.env` 模板

### R-2 · `/static/dist/js/utils.js` 404 → 工单列表空白
- **报错**：浏览器 console 404 → `bootstrapTable` 加载失败 → 列表不渲染
- **根因**：v1.14.0 上游**删了 `common/static/dist/` 整包**（5 个 css/js 文件），但 `base.html` 还在引用 `{% static 'dist/js/utils.js' %}`
- **解决**：从 v1.10.0 容器 `docker cp archery:/app/common/static/dist/ ./common/static/`，重跑 `collectstatic`
- **防重演**：MR 2 把 5 个 `dist/` 文件重新进 git 仓库（dev 维护，跟 v1.10.0 一样）
- **MR**：MR 2
- **影响面**：v1.14.0 上游删的，`/detail/` `/sqlquery/` 等所有页面受影响

### R-3 · Redis `127.0.0.1:6379` 连不上 → 500
- **报错**：`ConnectionError: Error 111 connecting to 127.0.0.1:6379`
- **根因**：redis 容器没做 host 端口绑定（`PortBindings: map[]`），host 进程 gunicorn 从 127.0.0.1 连不上
- **解决**：`.env` `CACHE_URL=redis://172.19.0.4:6379/0`（redis 容器 docker 网络 IP）
- **防重演**：升级脚本里加 `docker inspect archery_redis | grep IPAddress` 输出容器 IP，写入 `.env`
- **MR**：MR 1 配套 `.env` 模板

### R-4 · goinception 主机名解析失败
- **报错**：`goinception: Name or service not known`
- **根因**：v1.10.0 容器用 `goinception` 主机名（docker compose service name），host 进程解析不了
- **解决**：Django shell `update_or_create` 把 `sql_config.go_inception_host` 改成 IP `172.19.0.3`（自动用 `mirage` 加密存储）
- **防重演**：升级脚本里**先 dump sql_config**，升级后**自动 patch** `go_inception_host` 为新 IP
- **MR**：MR 1 配套 `.env` 模板

### R-5 · `/detail/<id>/` 报 500：sql_workflow.audit_driver 字段缺失
- **报错**：`OperationalError: Unknown column 'sql_workflow.audit_driver' in 'field list'`
- **根因**：dev 二次开发在 `sql/models.py:388` 加了 `audit_driver` 字段，**完全没建 migration 目录**。字段定义在代码里，DB 表里没有
- **解决**：
  ```sql
  ALTER TABLE sql_workflow
    ADD COLUMN audit_driver VARCHAR(32) NOT NULL DEFAULT 'archery' AFTER status,
    ADD COLUMN audit_fallback_reason VARCHAR(255) NOT NULL DEFAULT '' AFTER audit_driver;
  INSERT INTO django_migrations (app, name, applied) VALUES ('sql', '0001_dingtalk_oa_audit_driver', NOW());
  ```
- **防重演**：changelog 明确规定 dev 加字段必须 `makemigrations` 并 commit
- **MR**：MR 1
- **影响面**：下次任何环境重装 v1.14.0 + dingtalk_oa 都会爆

### R-6 · `sql/migrations/` 整个目录不存在
- **报错**：`No migrations directory at sql/migrations`
- **根因**：dev 改 model 时漏了 `makemigrations`
- **解决**：手动建 `sql/migrations/__init__.py` + `0001_dingtalk_oa_audit_driver.py`，admin.0001 已在 DB 用了 `dependencies=[]` 绕过一致性检查
- **防重演**：MR 1 提供标准 migration 模板；dev-发布checklist § 1.1 强制 `makemigrations --check --dry-Run` 无输出才能提 PR
- **MR**：MR 1

### R-7 · send_ding 误加 Archery 前缀（误判）
- **报错**：群里收不到通知（误判）
- **根因**：初判群机器人关键词是 "Archery"，实际关键词是 "工单"
- **解决**：patch 加了前缀，留着无害（防御性），真实消息含"工单"字样能过
- **防重演**：升级前**先在钉钉群机器人后台**查"安全设置"里的关键词，避免误判
- **MR**：MR 1 配套 patch

### R-8 · `notify.py` REJECTED/ABORTED 分支抛 NoneType 异常被吞
- **报错**：`AttributeError: 'NoneType' object has no attribute 'remark'`（被 logger.error 吞了）
- **现场**：驳回/终止工单 → 前端显示 `success=1` → **实际啥通知也没发**（典型静默失败）
- **根因**：`sql/notify.py:254` 和 `sql/notify.py:275` 直接访问 `self.audit_detail.remark`，但驳回/终止流程 `audit_detail` 可能为 `None`。`auto_notify` 的 `try/except` 把错误吞了
- **解决**：两处都加 None 保护
  ```python
  remark = self.audit_detail.remark if self.audit_detail else ""
  ```
- **防重演**：dev-发布checklist § 1.3 强制 `grep -n 'self.audit_detail\.' sql/notify.py` 必有 None 保护
- **MR**：MR 3
- **影响面**：所有驳回/终止工单**都受影响**，从 v1.10.0 时代就埋下

### R-9 · 3 个旧 supervisord 拉起的孤儿 qcluster 抢任务卡死
- **报错**：钉钉个人消息 0 到达（虽然 qcluster 新进程在跑）
- **根因**：v1.10.0 supervisord 启动的 3 个 qcluster 还在跑（PPID 是 `/opt/venv4archery/bin/supervisord`），能 pop 共享 redis 任务但 import v1.14.0 代码卡死。新任务全被它们抢走
- **解决**：
  ```bash
  pkill -9 -f 'venv4archery/bin/supervisord'      # 杀 3 个 supervisord
  pkill -9 -f 'venv4archery.*qcluster'             # 杀 3 个孤儿 qcluster
  systemctl start archery-v114-qcluster           # 启 systemd qcluster
  ```
- **防重演**：升级脚本里加 `pkill -9 -f 'venv4archery.*supervisord'`；dev-发布checklist § 4 加 `ps -ef | grep supervisord | grep venv4archery` 检查无输出
- **MR**：MR 4 + 升级脚本

### R-10 · `archery-v114-qcluster.service` systemd unit 缺失
- **报错**：`Unit archery-v114-qcluster.service not found`
- **根因**：原 04 脚本没建 qcluster unit，systemd 只管 gunicorn，qcluster 之前全靠手动 nohup 启
- **解决**：新建 unit 模板（17 行 systemd 219 兼容），`Restart=always` + `RestartSec=5`
- **防重演**：dev-发布checklist § 4 强制 `systemctl is-active archery-v114-qcluster` = `active`
- **MR**：MR 4
- **影响面**：qcluster 异常退出不会自动拉起，所有异步通知（钉钉个人消息、群消息备份入库）卡死

### 额外：10_upgrade.sh 中途异常退出（11 号）
- **报错**：`10_upgrade.sh: line 67: SET: unbound variable`（`set -e` 中断）
- **根因**：`curl $URL 2>/dev/null` 把 stderr 吞了但 `set -e` 还检测到非零退出码
- **解决**：脚本里所有 `curl` 加 `--silent --show-error` 或在 pipeline 后加 `|| true`
- **防重演**：升级脚本用 `set -e -o pipefail` 双重保险；新写脚本前**先在演练 192.168.70.171 跑一遍**
- **影响面**：第一次跑这个脚本会触发，下次跑前需要修

## 09 节点上线自检流程（新增）

**目的**：每次升级完成后，按 checklist 自检 12 条 R-N 是否重演。

```bash
# ===== 1. 静态资源 =====
curl -I http://172.20.2.110:9123/static/dist/js/utils.js   # 必须 200 (R-2)

# ===== 2. 数据库迁移一致性 =====
cd /dbdata/archery_v114
sudo -u archery venv/bin/python manage.py makemigrations --check --dry-Run   # 必须无输出 (R-5/R-6)
mysql archery -e "SELECT audit_driver, audit_fallback_reason FROM sql_workflow LIMIT 1;"  # 字段存在

# ===== 3. 异步通知链路 =====
sudo -u archery venv/bin/python manage.py shell -c "
from sql.notify import auto_notify
# 走一个驳回工单 + 一个终止工单（演练数据库或测试工单）
" 2>&1 | grep -i 'NoneType'   # 必须无输出 (R-8)

# ===== 4. systemd qcluster =====
systemctl is-active archery-v114-qcluster  # active (R-10)
ps -ef | grep 'venv4archery.*supervisord' | grep -v grep   # 必须无输出 (R-9)
kill -9 $(pgrep -f 'manage.py qcluster'); sleep 6
systemctl is-active archery-v114-qcluster  # 仍 active (自动拉起)

# ===== 5. 配置连通性 =====
sudo -u archery venv/bin/python manage.py shell -c "
from django.conf import settings
import redis
from common.config import SysConfig
print('CACHE_URL:', settings.CACHES['default']['LOCATION'])
redis.Redis.from_url(settings.CACHES['default']['LOCATION']).ping()  # R-3
sc = SysConfig()
print('go_inception_host:', sc.get('go_inception_host'))  # 应该是 172.19.0.x (R-4)
"

# ===== 6. ALLOWED_HOSTS =====
sudo -u archery venv/bin/python manage.py shell -c "
from django.conf import settings
print('ALLOWED_HOSTS:', settings.ALLOWED_HOSTS)
assert 'prodArchery.ahggwl.com' in settings.ALLOWED_HOSTS or '*.ahggwl.com' in settings.ALLOWED_HOSTS  # R-1
print('OK')
"
```
