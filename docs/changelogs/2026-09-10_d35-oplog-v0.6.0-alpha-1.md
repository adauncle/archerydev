## 阶段 1.2 detail_json 模板渲染 (json.dumps 字符串 -> key-value 表格)
**问题**: 之前 detail_json 在模板里直接 `<code>{{ log.detail_json }}</code>`, 业务方看 JSON 字符串很累
**修法**: view 端预解析 `log.detail_json` -> `log.detail_parsed` (dict), 模板按 action 类型分 5 种 schema 渲染:
- create / edit / enable / disable / one_click / bulk_import / add_table / delete_table / transform_change 9 类
- key-value 表格 (`<div class="kv-row"><span class="kv-key">改动字段</span><span class="kv-val">...</span></div>`)
- 旧->新 用 `→` 箭头, 变更高亮
- 关联: docs/plans/2026-09-10_d35-oplog-roadmap.html 阶段 1.2

## 阶段 1.3 库对配置前后 diff (edit 实际 old/new 值, 不是 changed_fields 列表)
**问题**: 之前 edit 只记 `changed_fields: ["sync_mode", "enabled"]`, 业务方看日志不知道"具体改了什么"
**修法**: pair_edit view 加 `changes` 字段, 记录每个字段的 old/new 实际值:
```python
detail = {
    "changed_fields": ["sync_mode", "enabled"],
    "changes": {
        "sync_mode": {"old": "blacklist", "new": "whitelist"},
        "enabled": {"old": False, "new": True},
    }
}
```
- enable/disable 详情也升级, 加 operate_from / operate_to 兼容字段
- 关联: docs/plans/2026-09-10_d35-oplog-roadmap.html 阶段 1.3

## 阶段 1.4 同步表增删埋点 (3 类新 action + 3 个新端点)

## 阶段 1.5 IP / User-Agent 记录 (合规审计)
**问题**: 之前审计日志没记 IP/UA, 合规审计缺失
**修法**: model 加 3 字段 + helper 加 request 参数自动拿:
- `client_ip = GenericIPAddressField(null=True, blank=True)` - 从 X-Forwarded-For (有反代时) 或 REMOTE_ADDR 拿
- `user_agent = CharField(max_length=256, blank=True, default="")` - HTTP_USER_AGENT 截断 256
- `is_backfilled = BooleanField(default=False, db_index=True)` - 1.1 历史数据补录脚本用, 上线先建好字段

helper `_write_audit_log(pair, action, operator, detail=None, request=None)`, 5 view 埋点都传 request:
```python
def _write_audit_log(pair, action, operator, detail=None, request=None):
    client_ip = None
    user_agent = ""
    if request is not None:
        xff = request.META.get("HTTP_X_FORWARDED_FOR", "")
        client_ip = (xff.split(",")[0].strip() if xff else request.META.get("REMOTE_ADDR")) or None
        user_agent = (request.META.get("HTTP_USER_AGENT", "") or "")[:256]
    ...
```

模板加 2 列 + 1 ↻ 标识 (1.1 补录用):
- 表格列 4: "IP / UA" (110px)
- 模板列 1: ID + `↻` 标识 (is_backfilled=True 时)
- CSS: `ddlsync-log-ip` (mono font) + `ddlsync-log-ua` (ellipsis 200px)

关联: docs/plans/2026-09-10_d35-oplog-roadmap.html 阶段 1.5

## 实战新发现 (跨项目可复用, 2 条)
1. **django_q schedule 避开 croniter 依赖** (D35 v0.6.0-alpha-1 实战新发现) - 跨项目用 django_q schedule 想用 cron 表达式, 必先 `pip show croniter` 看装没装. 没装的话用 `schedule_type="I" minutes=1440` (interval) 替代 `cron="0 3 * * *"` (D = daily cron). 实战踩坑: 134 dev + 110 prod 都没装 croniter, `ImportError: Please install croniter to enable cron expressions`
2. **view 端预解析 detail_json 比模板端 custom filter 简单** (D35 v0.6.0-alpha-1 实战新发现) - 跨项目做"详情 JSON 表格化渲染"功能, 优先 view 端 `import json; _log.detail_parsed = json.loads(_log.detail_json)` 传到模板, 别建 templatetags 写 custom filter. 实战踩坑: 模板端写 `{% load json_tags %}` + `{{ log.detail_json|safe_parse_json }}` 需要建 templatetags/json_tags.py + register.filter, 比 view 端 1 行代码复杂 10 倍
