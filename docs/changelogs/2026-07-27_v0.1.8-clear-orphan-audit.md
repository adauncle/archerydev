# v0.1.8-prod — 清 workflow_audit/audit_detail/log orphan + 重置 auto_increment

**日期**: 2026-07-27
**类型**: fix
**Tag**: v0.1.8-prod (待打)

## 问题

测试 /submitsql/ 提交 `CREATE TABLE test_marker (id int)`，弹窗：
```
{"errors": "该工单当前状态为待审核，请勿重复提交"}
```

但 `sql_workflow` 表完全空，工单根本没创建成功。

## 根因

v0.1.6-prod 我们清掉了 `sql_workflow_content` 的 4582 行 orphan 数据，但**漏了同批脏数据**：

| 表 | 行数（v0.1.8 修前） | 状态 |
|---|---|---|
| `sql_workflow` | 0 | 空 |
| `sql_workflow_content` | 0 | v0.1.6 已清 |
| `workflow_audit` | **4610** | **❌ orphan, 漏了** |
| `workflow_audit_detail` | **9533** | **❌ orphan, 漏了** |
| `workflow_log` | **27164** | **❌ orphan, 漏了** |

`workflow_audit.workflow_id` 全部指向不存在的 `sql_workflow.id`，但表里这些 audit 记录**没被清掉**。

新提交流程：
1. `workflow.save()` → `sql_workflow` 表空，auto_increment=1，INSERT id=1
2. `auditor.create_audit()` → 调 `wf.get_audit()` → `WorkflowAudit.objects.get(workflow_id=1, workflow_type=2)`
3. **命中历史的 orphan audit**（`audit_id=6, workflow_id=1, create_user='dinghaiyun'`）
4. 抛 `AuditException("该工单当前状态为待审核，请勿重复提交")`

每次失败提交 auto_increment advance 1（2, 3, 4, 5, 6...），**永远撞上**同批历史 audit 里的某个 `workflow_id=N`。

## 修复

```sql
DELETE FROM workflow_audit
WHERE NOT EXISTS (SELECT 1 FROM sql_workflow w WHERE w.id = workflow_audit.workflow_id);
-- 4610 rows

DELETE FROM workflow_audit_detail
WHERE NOT EXISTS (SELECT 1 FROM workflow_audit a WHERE a.audit_id = workflow_audit_detail.audit_id);
-- 9533 rows

DELETE FROM workflow_log
WHERE NOT EXISTS (SELECT 1 FROM workflow_audit a WHERE a.audit_id = workflow_log.audit_id);
-- 27164 rows

SET FOREIGN_KEY_CHECKS=0;
TRUNCATE TABLE sql_workflow_content;
TRUNCATE TABLE sql_workflow;
SET FOREIGN_KEY_CHECKS=1;
-- 重置 auto_increment 到 1
```

注：MySQL 8 的 `ALTER TABLE ... AUTO_INCREMENT = N` 当 N ≤ 当前 max(id) 时**会被忽略**。空表 max(id)=NULL 仍可能保留旧 advance 值，必须用 `TRUNCATE` 才能强制重置。

## 副作用

所有 v1.10.0 历史的 audit / detail / log 都删了。但 `sql_workflow` 本身也空着，没有这些 audit 也访问不到任何工单，留着只是负担。

## 为什么 v0.1.6 漏了这步

v0.1.6 我们修 `Duplicate entry '1' for key 'sql_workflow_content.uniq_workflow_id'` 时，只看了 `sql_workflow_content` 的 orphan（**唯一索引** 报错触发），没意识到 `workflow_audit` 的 `unique_together = ("workflow_id", "workflow_type")` 也有同样问题。

应该当时就把整个 v1.10.0 脏数据全清了。
