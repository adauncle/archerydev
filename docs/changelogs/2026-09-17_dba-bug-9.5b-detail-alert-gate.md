UX 误导(业务方以为系统有问题)。修法: detail 视图 + template 双层加 `enable_gh_ost` 守卫。

## 根因 (DBA-bug-9.5b 实战新发现)

DBA-bug-9.5 阶段(commit `4b1e415`) 改造 detail 页加非 ALTER 警告时:
- `views.py` detail 视图无条件计算 `non_alter_stmts = _detect_non_alter(sql_text)` (line 508)
- `detail.html` `{% if non_alter_stmts %}` 也没看 `enable_gh_ost`
- 后果: 工单没勾 gh-ost 时,警告还显示, UX 误导

预期: 只有勾 gh-ost 才该警告(否则是无关场景, 业务方没要求 gh-ost, 系统不该给 gh-ost 拒绝警告)

## 实战新发现 (2 条, 跨项目可复用)

### 1. detail 页警告块必加 enable_gh_ost 守卫 (DBA-bug-9.5b, 跨项目 UX bug)
跨项目写工作流 / SQL 平台时, detail 视图的"模式不支持"警告必须看实际 mode 标志,
不能只看 SQL 内容 — 否则 UX 误导(业务方以为系统有问题, 实际没勾)。
- 修法: 双层防护 — views.py 跳过计算 + template `{% if workflow_detail.enable_xxx %}`

### 2. 跨 commit 部署必查 git diff --stat (跨环境部署教训)
跨项目部署 commit A 后的 commit B 改动时, 必查 `git diff A..B --stat` 列全所有 modified 文件,
漏 1 个文件就可能让生产环境 AttributeError(Python 模型跟 db 字段不一致)。
