# v0.1.9-prod — 装 qcluster (django-q2 systemd) + 钉钉 OA 通知可观测性

**日期**: 2026-07-27
**tag**: `v0.1.9-prod`
**commit**: (TBD by `git tag -a` after this commit)

## 问题

用户提交工单后，**马克群没看到钉钉工作通知**。

诊断发现：
1. `notify_for_audit` 在 `sql_api/api_workflow.py:142` 通过 `async_task(...)` 提交到 django-q2
2. django-q2 通过 `Q_CLUSTER.django_redis="default"` 写入 `redis://127.0.0.1:6379/0` 的 `django_q:archery:q` 列表
3. 但**生产服务器上没有运行 qcluster worker**（`Unit django-q2.service could not be found.`），
   导致任务一直堆在 redis 队列里没人消费
4. 即使 qcluster 跑起来，**默认 logger level=WARNING**，成功推送只写 `logger.debug`，
   `qcluster.log` / `archery.log` 不会有任何记录 —— 运维盲区

## 改动

### 1. 新增 systemd unit: `archery-prod-qcluster.service`

部署在 `/etc/systemd/system/archery-prod-qcluster.service`（17 行 systemd 219 兼容），
跟现有 `archery-prod-gunicorn.service` / `goinception.service` 一致。

- `ExecStart=/opt/archery/prod/venv/bin/python manage.py qcluster`
- `Environment=ARCHERY_LOG_LEVEL=INFO`（qcluster 默认开 INFO，方便异步任务可观测）
- `WorkingDirectory=/opt/archery/prod`
- `EnvironmentFile=/opt/archery/prod/.env`
- `Restart=always`, `RestartSec=3`
- 日志 `StandardOutput=append:/opt/archery/prod/logs/qcluster.log` +
  `StandardError=append:/opt/archery/prod/logs/qcluster.log`

部署：
```bash
systemctl daemon-reload
systemctl enable --now archery-prod-qcluster
```

验证：7 个 worker 子进程，redis `LLEN django_q:archery:q=0`，
`blocked_clients: 1` (BLPOP 阻塞等待)。

### 2. `common/utils/sendmsg.py` - `MsgSender.send_ding2user_via_oa` 成功时改 `logger.info`

`send_ding2user_via_oa` 调用钉钉 OA `topapi/message/corpconversation/asyncsend_v2` 后，
原本只在 `errcode == 0` 时写 `logger.debug`。**而 default logger level=WARNING，
所以即使 qcluster 真的成功推送了通知，磁盘上也没任何记录**。

改为 `logger.info`，且加 `CUSTOM-MODIFIED` 注释。

### 3. `archery/settings.py` - logger level 走 `ARCHERY_LOG_LEVEL` env var

`default` / `django-q` 两个 logger 的 `level` 字段从硬编码 `"WARNING"` 改为
`env("ARCHERY_LOG_LEVEL", default="WARNING")`。

- 默认行为跟上游一致（WARNING）
- qcluster service 加 `Environment=ARCHERY_LOG_LEVEL=INFO` 后能看到完整异步任务日志
- gunicorn 继续走 WARNING（不污染 access 日志）

加 `CUSTOM-MODIFIED` 注释。

## 副作用 / 注意事项

- `archery.log` 会出现 INFO 级别行（仅 qcluster 进程写时），不会影响 gunicorn 进程（gunicorn 没设这个 env var）
- `qcluster.log` 才开始有内容（之前一直是 0 字节）
- `django_q_task` 表仍由 `Q_CLUSTER.save_limit=0` 控制不写记录，正常
- redis `django_q:archery:q` 队列消费完自动清空，正常
- 新装的 `archery-prod-qcluster` 已 enable + start，server reboot 后自动起
