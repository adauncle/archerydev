#### 0.1 当前数据同步到历史库 — 两个流程

| 流程 | 工具 | 方式 | 链路 | 特点 | 风险 |
|------|------|------|------|------|------|
| **① DML 数据同步** | 科大国创数据同步组件 | **按时间戳增量** 拉取业务库新增/修改的数据 | 业务库 → 科大国创 → 历史库 | 自动化, 准实时 (分钟级), 业务 RD 不参与 | 依赖历史库 schema 跟业务库一致 |
| **② DDL Schema 同步** | **无, 纯人工** | DBA 凭经验判断 → 人工到历史库跑 SQL | 业务 RD → Archery → 业务库 DDL → DBA 收通知 → DBA 人工执行 | 人工操作, 没有自动校验, 没有强制流程 | **DBA 漏同步 / 同步出错 / 同步延迟** |

> 关键点: DML 走自动化组件没问题, **DDL 走人工是当前最大风险**。

#### 0.2 痛点 · DDL 人工同步 5 个具体问题

| # | 痛点 | 现状 | 风险等级 |
|---|------|------|----------|
| 1 | **DBA 人工执行, 容易漏** | 每天 DDL 工单 5-20 条, DBA 凭记忆/经验判断 | **高** |
| 2 | **没有自动校验** | 业务库 DDL 跑通 ≠ 历史库 DDL 跑了 | **高** |
| 3 | **同步不及时** | DBA 下班前集中处理, 延迟 4-8h | **中** |
| 4 | **跨业务库多库容易配错** | hly_accesscard / hly_activity / hly_doc_model 多库 | **中** |
| 5 | **DML 同步依赖 DDL 先同步** | 历史库没 DDL → 科大国创整条挂 | **高** |

#### 0.3 影响 · DDL 漏同步的真实业务影响链路

5 阶段链路:
1. **T+0 当天**: 业务库 DDL 执行成功, 业务 RD 不知道历史库没同步 (DML 在偷偷失败重试)
2. **T+1 第二天**: 科大国创 DML 同步任务**整体失败** (业务库加字段, 历史库没, INSERT 报错)
3. **T+1 ~ T+3**: 下游大数据 (数据仓库 / 报表 / 风控 / 决策支持) 读历史库, "昨天数据没进来" / "缺字段" / "JOIN 失败"
4. **T+3+**: 业务方反馈"报表数据延迟" / "数据缺漏" / "对账不平", 反查才发现
5. **DBA 介入**: 手动补执行历史库 DDL + 手动重跑 DML 同步任务, 修复 1-4h, **下游数据延迟 1-3 天**

> 真实案例 (8/27 实战): 110 prod 业务库 `hly_doc_model` 7.28M rows test 表 gh-ost 改字段 · 历史库 DDL 漏同步 → 科大国创整条同步链路挂 · 下游数据仓库延迟 2 天。

#### 0.4 新功能 v0.5.0 DDL 跨库同步 — 解决什么痛点, 达成什么目标

**新功能**: 业务库 DDL 触发后, Archery **自动**在历史库生成镜像 DDL 工单, 走跟正常历史库工单一样的流程 (8/28 r3 拍板: 走当前配置的流程, 0 额外代码)。

解决的痛点 (5 对应 0.2):

| 痛点 (0.2 序号) | v0.5.0 解法 |
|------|------------|
| 1 · 漏同步 | 业务库 DDL 审过自动触发历史库镜像工单, **0 漏同步** |
| 2 · 没校验 | 业务库 DDL 必审过 (`current_status=1 PASSED`) 才触发 |
| 3 · 不及时 | **T+0 实时触发**, 不再下班前集中处理 |
| 4 · 跨多库配错 | DBA 配库对时 `WHERE TABLE_SCHEMA LIKE 'hly%'` 跨多库 |
| 5 · DML 同步挂 | **DDL 0 漏同步 → DML 同步永久稳定** |

达成的核心目标 (5 个):
1. **DDL 0 漏同步** — 不依赖 DBA 人工记忆
2. **下游大数据 0 延迟** — DDL T+0 同步, 业务方无感知
3. **DBA 配表 1-click 完成** — 一键配机制 (1589/1289 实战数据 6 min 配完, r2)
4. **DML 同步永久稳定** — 历史库 schema 跟业务库永远 1:1 同步
5. **历史库工单跟正常工单一样** — 0 额外代码, DBA 改"历史库组" 流程就生效 (r3)
