# 2026-07-21 · v0.1.2-prod 改 systemd 管理 gunicorn

## 背景

之前 v0.1.0-prod 的 gunicorn 是用 `nohup bash -c '... &'` 启的，要查 PID 用 pgrep，停服靠 `pkill`。
用户要求简化运维，改成 systemd 管理 —— `systemctl {start|stop|restart|status}` 一行搞定。

## 切换过程踩到的 3 个坑

### 坑 1：systemd 219 "Unit not found" cache bug

`daemon-reload` + `enable` 都成功，但 `start` 报 "Failed to start ... Unit not found"。
即使 `list-units` 显示 unit 是 `loaded` 状态也不行。

**根因**：unit 文件里用了 systemd 230+ 才稳定的指令（`ProtectSystem=strict` / `ReadWritePaths=` / `MemoryMax` / `StartLimitInterval`），systemd 219 解析失败但 unit 文件仍被加载成"语法错误但能识别"的状态，启动时直接拒绝。

**修复**：把 unit 砍到**最简 17 行**，只保留 219 兼容指令：
- ✅ `Type=simple` / `User=` / `Group=` / `WorkingDirectory=` / `EnvironmentFile=` / `ExecStart=` / `Restart=always` / `RestartSec=` / `LimitNOFILE=`
- ❌ 删 `NoNewPrivileges` / `ProtectSystem` / `ProtectHome` / `PrivateTmp` / `ReadWriteDirectories`（219 都不支持/不稳定）
- ❌ 删 `StartLimitInterval/Burst`（219 没这俩指令）
- ❌ 删注释和 `##` 头部（systemd 219 解析有警告，少数情况会拒绝）

### 坑 2：SELinux context 错

`/etc/systemd/system/archery-prod-gunicorn.service` 的 SELinux context 是 `system_u:object_r:usr_t:s0`。
systemd 期望的是 `systemd_unit_file_t`，错了 SELinux 会拦截。

**修复**：
```bash
chcon -v -t systemd_unit_file_t /etc/systemd/system/archery-prod-gunicorn.service
# 6 个 archery unit 全部修
```

> 这是 init 脚本（`scripts/deploy/01_init_server.sh`）里漏的 —— scp 文件时没保留 SELinux context。
> 后续 init 脚本应该加 `restorecon -R /etc/systemd/system/archery*` 自动修。

### 坑 3：dbops.service 死循环占满 systemd job queue

服务器上有个 `dbops.service`（别人的服务）找不到 `/dbdata/dbops/app/venv/bin/uvicorn`，
但 `Restart=always` + `RestartSec=10` 让它每 10 秒重试一次，
systemd job queue 被这个占着，archery unit 启动排队异常。

**修复**：
```bash
systemctl stop dbops.service
systemctl disable dbops.service
```

（确认不是我们用的服务；如果在用，得修 uvicorn 路径。）

## 现在的 unit 文件（17 行）

```ini
[Unit]
Description=Archery Production Gunicorn (port 9003, 4 workers)
Documentation=https://github.com/adauncle/archerydev
After=network.target mysqld.service redis.service

[Service]
Type=simple
User=archery
Group=archery
WorkingDirectory=/opt/archery/prod
EnvironmentFile=/opt/archery/prod/.env

ExecStart=/opt/archery/prod/venv/bin/gunicorn archery.wsgi:application \
    -w 4 \
    -b 0.0.0.0:9003 \
    --access-logfile - \
    --error-logfile - \
    --timeout 120

Restart=always
RestartSec=5
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

## 操作简化对比

| 操作 | v0.1.1（nohup） | v0.1.2（systemd） |
|------|---------------|------------------|
| 启动 | `sudo -Hu archery bash -c 'cd /opt/archery/prod && set -a && source .env && set +a && /opt/archery/prod/venv/bin/gunicorn ... &'` | `systemctl start archery-prod-gunicorn.service` |
| 停止 | `pkill -TERM -f 'gunicorn.*9003'; sleep 5; pgrep ...` | `systemctl stop archery-prod-gunicorn.service` |
| 重启 | 组合 stop + start | `systemctl restart archery-prod-gunicorn.service` |
| 状态 | `ps -ef \| grep gunicorn \| grep -v grep` | `systemctl status archery-prod-gunicorn.service` |
| 开机自启 | 写 cron `@reboot` 或 init 脚本 | `systemctl enable archery-prod-gunicorn.service` |
| 日志 | `tail -f /var/log/archery/prod-gunicorn.log` | `journalctl -u archery-prod-gunicorn.service -f` |

## 修复步骤

1. 备份老 unit（`cp /etc/systemd/system/archery-prod-gunicorn.service /tmp/archery-prod-gunicorn.service.bak`）
2. 写最简 unit 覆盖
3. `chcon -t systemd_unit_file_t` 修 SELinux context
4. `systemctl daemon-reload`
5. `systemctl start archery-prod-gunicorn.service` —— 报"Unit not found" 时再清 `dbops.service` 释放 job queue
6. `systemctl enable archery-prod-gunicorn.service` 开机自启
7. 验证：`systemctl status` + `curl http://127.0.0.1:9003/login/`

## 已验证

- ✅ `systemctl start / stop / restart` 三件套正常
- ✅ `Active: active (running)` Main PID 45900（第一次启动）→ 49556（restart 后）
