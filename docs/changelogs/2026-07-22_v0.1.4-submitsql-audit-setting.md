# v0.1.4-prod — 修复 /submitsql/ 审批流程下拉为空

**日期**: 2026-07-22
**类型**: fix
**Tag**: v0.1.4-prod (待打)

## 问题

测试 /submitsql/ 提交流程时，点击「SQL检测」弹窗提示 "请配置审批流程！"，下拉框为空。

## 根因

`/submitsql/` 页面通过 `sql/utils/workflow_audit.py:691` 的 `Audit.settings(group_id, workflow_type)` 方法读取 **上游** `workflow_audit_setting` 表来决定审批人下拉的内容。

我们 `setup_demo_data.py` 只插了**新驱动系统**的 `ext_approval_flow` 和 `ext_approval_policy` 表，但**忘了补**上游 `workflow_audit_setting` 表里 `group_id=25` (测试组) 的默认审流。

两套表是平行的：
- **上游 `workflow_audit_setting`** → 决定前端表单下拉里能看到哪些 auditors
- **新 `ext_approval_flow`** + `ext_approval_policy` → 决定**实际提交时**走哪个 driver

不补上游表 → 下拉是空的 → 表单校验失败 → 弹"请配置审批流程"。

## 修复

1. **补一条 `workflow_audit_setting` 记录** (id=29):
   ```sql
   group_id=25, group_name='测试组',
   workflow_type=2 (SQL_REVIEW), audit_auth_groups='3' (DBA 组)
   ```

2. **更新 `setup_demo_data.py`**: 第 8 步增加 `WorkflowAuditSetting.objects.update_or_create(...)`，让 demo 数据脚本可重复运行且不会漏。

## 验证

```python
>>> Audit.settings(group_id=25, workflow_type=2)
'3'  # 之前是 None
```

刷新 `/submitsql/` 页面，审批流程下拉显示 "DBA"（来自 `auth_group` id=3），表单校验通过。

## 提交时实际行为

- 提交 SQL → `ConfigurableAuditor` 重新匹配 `ext_approval_policy`：
  - 高风险 (rows≥100, DDL/DML) → 命中 `dingtalk_oa` flow → 因 process_code 是 PLACEHOLDER，降级为 `archery` driver
  - 中风险 (10≤rows<100) → 命中 `archery` normal flow
  - 低风险 (rows<10) → 走默认 `default` flow (audit_auth_groups=3, fallback DBA 内审)
