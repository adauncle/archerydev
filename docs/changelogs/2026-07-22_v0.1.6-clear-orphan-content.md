# v0.1.6-prod — 清掉 sql_workflow_content orphan 数据

**日期**: 2026-07-22
**类型**: fix
**Tag**: v0.1.6-prod (待打)

## 问题

测试 /submitsql/ 点「SQL提交」时弹窗：
```
{"errors":"(1062, \"Duplicate entry '1' for key 'sql_workflow_content.uniq_workflow_id'\")"}
```

## 根因

v1.10.0 → v1.14.0 升级时的脏数据：

| Table | 状态 |
|-------|------|
| `sql_workflow` | **空表** (0 rows, max_id=None) |
| `sql_workflow_content` | 4582 rows，**全部 orphan** |
| `workflow_audit` | 4610 rows (历史审计) |
| `workflow_audit_detail` | 9533 rows |
| `workflow_log` | 27164 rows |

新提交流程：
1. `workflow = SqlWorkflow(**workflow_data); workflow.save()` → 新行 id=1（auto-increment 从 1）
2. `SqlWorkflowContent.objects.create(workflow=workflow, ...)` → workflow_id=1
3. 但 `sql_workflow_content` 里 `workflow_id=1` 已存在（v1.10.0 旧数据）→ **1062 Duplicate**

## 修复

```sql
DELETE FROM sql_workflow_content
WHERE NOT EXISTS (SELECT 1 FROM sql_workflow w WHERE w.id = sql_workflow_content.workflow_id);
```

- 4582 行 orphan 全清
- `sql_workflow_content` 现在 0 行
- `sql_workflow` auto_increment=2（说明之前已经成功 INSERT 过 1 次但内容失败）
- 后续新提交会从 workflow_id=2 开始，干净

## 副作用

旧 v1.10.0 工单的 content 数据丢失。**但**:
- `sql_workflow` 表本身就是空的（v1.14.0 升级时被清）
- 没有 content 就访问不到这些工单
- 留着 4582 行 orphan 反而是负担

所以**清空是正确的选择**。

## 不影响

- `workflow_audit` / `workflow_log` / `workflow_audit_detail` 也都是 v1.10.0 残留
- 但这些是 audit 历史的一部分（虽然 workflow_id 指向不存在的 id）
- 用户没要求清，保持不动
- 如果以后想清: `DELETE FROM workflow_audit WHERE NOT EXISTS workflow;`
