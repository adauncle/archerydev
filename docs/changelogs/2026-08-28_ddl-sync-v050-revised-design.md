# 8/28 DDL 跨库同步 v0.5.0-r1 修订设计 (批量导入 + 黑名单 + 增量同步)

## 背景
- 8/21 v0.5.0 初版设计稿写完, 8/22-8/27 实战推 110 + gh-ost 收尾占满
- 8/28 复审 8/21 设计稿时, DBA 阿达叔叔提了**核心问题**: "同步白名单如何配置, 历史库大几百张表"
- 8/21 设计是"DBA 手动一张张点加同步表", 历史库 500 张表 = DBA 点 500 次, **完全不现实**

## 核心修订 (3 个)

### P0 · 批量导入机制 (核心)
- **8/21 原版**: 库对详情页逐张点 "添加同步表" 按钮
- **8/28 修订**: 库对详情页加 "📥 批量导入" 按钮, 弹模态框:
  - 后端从历史库 INFORMATION_SCHEMA.TABLES 扫表
  - 前端模态框显示所有表 + 全选/反选/搜索
  - 过滤规则: 排除前缀 (_log/_bak/_tmp/_test) + 排除后缀 (_history/_archive/_backup) + 排除 ENGINE (MEMORY/BLACKHOLE) + 仅保留 size > 0 的表
  - DBA 一次操作搞定 80% 工作量 (500 张表 → 5 分钟配完)

### P0 · 同步模式默认改 blacklist
- **8/21 原版**: sync_mode 默认 `whitelist` (DBA 显式选要同步的, 适合小表场景)
- **8/28 修订**: 改默认 `blacklist` (业务库 80% 表都同步, 显式排除 20% 不要的, 适合大表场景)
- blacklist 模式 + 批量导入: DBA 工作量从 500 次点降到 1 次批量 + 50 个排除

### P1 · 增量同步机制 (Phase 2)
- **问题**: 业务库加新表, DBA 容易漏配库对白/黑名单, 几个月后同步挂才被发现
- **解法**: 业务库 DDL 工单提交时, Archery 自动检测新表是否在历史库:
  - 在白名单: 正常联动
  - 不在白名单 + 历史库有同表: 工单详情页提示 "检测到新表 `xxx` 未配置, 1-click 加白名单/黑名单"
  - 不在白名单 + 历史库无此表: 不联动

### P2 · schema 差集工具 (Phase 3)
- **问题**: 库里已有 100+ 张表, DBA 想知道"哪些列/索引漏同步了"
- **解法**: 库对巡检结果页面展示 schema 差集 (列/索引 diff), DBA 一眼看到 "漏同步了哪些"

## 教训 (跨项目可复用)

1. **二次开发设计稿写完不是结束, 实战前要复审** — 8/21 写完设计稿没及时复审"实际工作量", 8/28 DBA 提"历史库几百张表"才发现"DBA 手动配 500 次"不现实. **写完设计稿必找 1-2 个真实场景算工作量, 不然就拍脑袋.**
2. **白名单 vs 黑名单 默认值要看场景** — 8/21 默认 whitelist 是按"小表"场景拍板, 8/28 实际场景是"业务库 500 张表全要同步"应改 blacklist. **拍板默认值必演 2-3 个真实业务库表数, 决定默认走白/黑名单.**
3. **批量操作是工业级产品的标配** — DBA 不可能手动配几百张表, 任何"配 N 张表/加 N 个 perm/建 N 条记录"场景必加批量. **设计稿审"配 N 条记录"环节, 必演批量操作 UX + 性能.**
