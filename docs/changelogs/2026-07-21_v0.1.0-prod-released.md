## 部署踩到的坑（已修复，文档化）

1. **set -e + grep 退码 1**（commit 6b9dfee）
   - `mysql ... | grep -v 'Using a password'` 当 mysql 只输密码告警时 grep 退码 1 → 脚本静默死
   - 改用 `mysql_run()` 包装 + `2>/dev/null`

2. **升级 SQL ALTER/CREATE 已存在错误**（commit 9b80397）
   - v1.1.0/v1.2.0/v1.5.0/v1.10.0 等升级 SQL 缺 `IF NOT EXISTS`，裸跑 set -e 会死
   - 加 `|| true` 兜底

3. **/opt/archery/prod 仓库落后本地**（commit 7ea64a6）
   - prod 在 9e2a75d，本地已到 b99dbda，`pymysql-replication>=0.45` 坏行还在 → pip 装失败
   - 加 `step 0.5 git pull`

4. **dingtalk_oa 0001_initial.py 漏 commit**（commit 78158a3）
   - coder agent 之前只写 models 没跑 `makemigrations`，文件没进 git
   - 在 prod 上临时生成、SCP 回本地、commit push

5. **auth_group.sql 多表 fixture 失败**（commit faf3852）
   - `sql_instance_tag` 和 Django 自动建的 `auth_group(id=1)` 都已存在
   - 改用 `mysql --force` 让 sql 继续跑后面的 auth_group 插入
   - 另写 fix_auth_group2.sh 手动补 5 个组 + IGNORE 权限绑定

6. **migrate 输出被 tail -5 截断**（commit faf3852）
   - 看不出哪个 app 没 migrate 通过
   - 加 `makemigrations --dry-run` 检查

## 用户需要做的事

prod 已经 100% 跑通，**用户侧剩余配置**（admin UI 操作）：

1. **改 audit_auth_groups 占位值**：admin → 钉钉 OA → Approval flows → 选 `default` → 把 `audit_auth_groups` 从 `'1,2'` 改成实际审批组 ID（建议 `3` = DBA）

4. **填 DINGTALK_OA_* 5 个值**：APP_KEY / APP_SECRET / AGENT_ID / CALLBACK_TOKEN / CALLBACK_AES_KEY
5. **配 DINGTALK_NOTIFY_WEBHOOK**：DBA 群机器人
