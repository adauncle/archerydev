# D38 续 5: 审批人组 (lisp) 只能看不能操作 (2026-09-09 14:50)

## 业务方反馈
- 9/9 14:42 业务方截图: 李绍平 (lisp) 访问 /gh_ost/admin_list/ 能看全量 (15 条任务), 但操作列显示了"查看 + 回滚"两个按钮
- 业务方反馈: "操作对应两个按钮, 查看和回滚. 仅允许他查看"

## 根因 (D35 推的设计漏洞)
- D35 9/7 实战拍板: 副总场景 (李绍平) 单独建"审批人"组, 只用来"看全量", 不应该有 cancel/retry/rollback 等高危操作
- **但 D35 推的代码用了同一个 `is_admin_or_dba` 判定**:
  - `task_list.html:235` `{% if is_admin_or_dba %}` → cancel/retry/rollback 按钮
  - `task_list.html:270` `{% if is_admin_or_dba %}` → 底部 AJAX 提示
- `is_admin_or_dba` 包含"审批人"组 (True) → 审批人组也能看到操作按钮 (跟设计意图冲突)

## 修法: 新加 `_can_operate_gh_ost()` helper
- 新 helper 只含 superuser / DBA / DBA组长 (**不含审批人组**)
- view admin_list 加 `can_operate` context 变量
- 模板 line 235 + 270 `is_admin_or_dba` 改 `can_operate`

### 改动 2 个文件
1. `sql/extensions/ddl_gh_ost/views.py` (line 1137-1163) - 加 `_can_operate_gh_ost()` helper
2. `sql/extensions/ddl_gh_ost/views.py` (line 1049-1106) - admin_list view 加 `can_operate` context
3. `sql/extensions/ddl_gh_ost/templates/ddl_gh_ost/task_list.html` (line 232-245) - cancel/retry/rollback 按钮判定从 `is_admin_or_dba` 改 `can_operate`

## D38 续 5 实战新发现 (跨项目可复用)
1. **D35 推的"审批人"组设计漏了"操作"维度** (D38 续 5 实战新发现) - D35 拍板"审批人"组只用来"看全量"审批, 但代码用 `is_admin_or_dba` 判定 cancel/retry/rollback 按钮, 跟设计意图冲突. 跨项目做"看 X 不能操作 X"的设计, 必拆 2 个 helper (看 / 操作), 不要共用一个判定
2. **"审批人"组 + 端点硬墙双层防护** (D38 续 5 实战新发现) - 前端按钮 `can_operate` 隐藏, 后端 `_require_change_perm` 端点硬墙 (即使审批人组前端能看到按钮, 端点也会 403). 跨项目做权限分级, 必前后端双层防护, 不能只靠前端隐藏
3. **force_login 4 组合演练是验证"角色分组"的金标准** (D38 续 5 实战新发现) - archery/dba/mkq/lisp 4 用户演练看 is_admin_or_dba + can_operate + 按钮数量, 100% 验证审批人组只读生效. 跨项目做权限/角色, 必演练 N 角色 (superuser / 真组 / 边缘组) 验证
