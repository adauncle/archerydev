## 交付清单

### 新增

- `sql/extensions/ddl_gh_ost/services/runner.py`
  - `build_ghost_command(task, instance)` 构造 gh-ost CLI 参数
  - `start_ghost_process(task, instance)` Popen + nohup + 日志到 /var/log/archery/gh_ost/
  - `stop_ghost_process(pid, timeout)` SIGTERM → SIGKILL
  - `is_alive(pid)` `read_log_tail(path, max_bytes)` 工具

- `sql/extensions/ddl_gh_ost/services/parser.py`
  - `parse_ghost_log(text) -> GhostParseResult` 解析 gh-ost 1.1.10 输出
  - 识别 Copy: N/M P% / Waiting for cut-over / Cut-over complete / Done / FATAL
  - 兼容 `Time: 11s(total)`（括号）和 `Done migrating xxx`（非行尾）

- `sql/extensions/ddl_gh_ost/services/poller.py`
  - `start_poller(task_id)` 启 daemon thread
  - `poll_loop(task_id)` 主循环：3s 读 log → 解析 → 写 progress → 状态机推进
  - `_query_threads_running(instance)` 查 MySQL Threads_running
  - `_maybe_pause_resume(task, instance)` 超阈值 SIGSTOP，低于阈值 SIGCONT
  - `_finalize_task(task, status, error)` 终态收尾 + 钉钉通知
  - **外层 try/except 兜底**：任何未捕获异常写 task.error_message + 切 failed

- `sql/extensions/ddl_gh_ost/services/notify.py`
  - `notify_terminal(task)` 终态发钉钉 webhook（best-effort）
  - Markdown 格式：状态徽章 + 工单 + ALTER + 发起人 + 耗时 + 错误（如有）

- `sql/extensions/ddl_gh_ost/management/commands/cleanup_ghost_tables.py`
  - `python manage.py cleanup_ghost_tables [--days N] [--dry-run]`
  - 清理 status in (failed/cancelled/rolled_back) + finished_at < cutoff 的影子表
  - django-q2 调度：`schedule("...cleanup_ghost_tables", schedule_type="D", next_run=...)`

## gh-ost CLI 参数（runner.build_ghost_command）

```
gh-ost --host=$HOST --port=$PORT --user=$USER --password=$PASS
  --database=$DB --table=$TABLE --alter="$ALTER"
  --assume-rbr --allow-on-master --execute
  --exact-rowcount --concurrent-rowcount
  --max-load=Threads_running=$THRESHOLD
  --nice-ratio=0
  --cut-over=atomic
  --initially-drop-ghost-table --initially-drop-old-table --ok-to-drop-table
  --verbose --default-retries=120
```

凭据走 settings.CUSTOM_GH_OST_PRECHECK_*（与 precheck 共用），生产留空则用 instance 字段。

## 已知问题 / 改进点

- **poller 偶发被打断**：daemon thread 异常没立刻浮出，加了外层 try/except 后能写 error_message；DBA 看 admin 详情可定位
- **cancel 后 is_alive=True 短时间窗口**：gh-ost 收 SIGTERM 后清理 socket/锁需要几秒，is_alive 用 SIGTERM 信号探测，会在进程真退前返回 False
- **DINGTALK_NOTIFY_WEBHOOK 未配**：134 dev .env 没设，notify_terminal 自动 skip；110 prod 配了之后会发
- **暂停阈值未真验证**：134 dev Threads_running 不会超过 30；生产高峰期可触发 SIGSTOP
