字段 diff 检测

DDL 提交前
先看清会改什么

Archery v0.3.0-beta 集成 8 维字段 diff 检测 + 11 条风险规则。业务 RD 提交 ALTER TABLE 时, 系统自动比对目标表当前结构,逐维度列出"什么会变",高风险时弹窗 DBA 兜底确认。

1 业务 RD 提交 DDL 的痛点

❌ 痛点 1:DDL 提交后才"惊吓发现"副作用

业务 RD 写 DDL 时,只看自己改的那一列,不知道其他列/索引/默认值会怎样变。

  • VARCHAR(256) → VARCHAR(128):已有数据被截断,但 RD 不知道
  • DEFAULT 'a' → DEFAULT NULL:历史数据 NULL,应用层 NPE
  • CHARACTER SET utf8 → utf8mb4:索引长度超 767 byte 限制,索引失效
  • DROP COLUMN:应用层还在用这个字段,线上报错

❌ 痛点 2:回滚成本高

DDL 走完了才发现问题,回滚要走完整 DDL reverse 流程。

  • 144MB 大表 DDL:走完 5-10 分钟,reverse 又是 5-10 分钟
  • 字段 diff 不知道变了哪些维度,reverse 不一定 100% 还原
  • 主从延迟期间 reverse:从库跟主库不一致,业务可能读到旧值
  • 应用层已经按新 schema 跑了:回滚 schema 但应用层代码已发布
根因: 业务 RD 写 DDL 时是"局部视角",只想着"我要加/改什么",但忽略了"会动其他什么"。 没有工具在提交前做"全局 diff 提醒",上线后才发现。

2 解决方案:8 维字段 diff + 11 风险规则

Archery 在 SQL 检测结果页 + 工单详情页都集成了字段 diff 端点 /gh_ost/column_diff/:

1

解析 ALTER TABLE

从 SQL 文本里解析目标表名 + 第一条 ALTER,提取 column_definition。

2

查 information_schema

连目标 MySQL 查 COLUMNS / STATISTICS / INDEXES 拿原表结构。

3

8 维 diff 对比

逐维度对比新旧 schema:类型/长度/字符集/排序规则/默认值/可空性/注释/索引。

4

11 风险规则

基于 diff 结果跑 11 条风险检查,分高/中/低 3 档,高风险弹 DBA 兜底。

8 维字段 diff 列表

维度说明示例
1. 数据类型 从一种类型变到另一种 (隐式转换风险) bigint → varchar(32) (类型转换 + 长度变化)
2. 长度 同类型但长度变 (数据截断风险) varchar(256) → varchar(128) (已有数据可能截断)
3. 字符集 字段字符集变化 (索引失效 + 隐式转换) utf8 → utf8mb4 (索引长度翻倍)
4. 排序规则 collation 变化 (查询结果可能不同) utf8mb4_general_ci → utf8mb4_bin (大小写敏感)
5. 可空性 NULL / NOT NULL 变化 (应用层需要适配) NULL → NOT NULL (历史 NULL 数据会报错)
6. 默认值 DEFAULT 变化 (已有数据保持旧值,新数据走新值) DEFAULT 'a' → DEFAULT NULL
7. 注释 字段 COMMENT 变化 (业务描述) COMMENT '老' → COMMENT '新'
8. 索引关联 字段被索引覆盖时的副作用 改长度后索引 767 byte 限制触发

11 条风险规则

高
1. 数据截断风险 长度缩小 + 已有数据可能超过新长度 (VARCHAR(256)→VARCHAR(128))
高
2. 类型转换风险 大数据类型 → 小数据类型 (bigint→int, decimal(10,2)→decimal(5,2))
高
3. NOT NULL 约束冲突 NULL → NOT NULL 时历史 NULL 数据会导致 ALTER 失败
高
4. 索引失效 utf8→utf8mb4 字符集变化导致索引长度超 767 byte 限制 (单列最大索引 3072 byte)
中
5. 默认值变化 新 DDL 的 DEFAULT 跟历史数据不一致,可能业务逻辑 break
中
6. 排序规则变化 collation 变化导致查询结果顺序变化 (utf8mb4_general_ci → utf8mb4_bin 大小写敏感)
中
7. 注释业务描述丢失 字段 COMMENT 被覆盖,数据治理文档需要同步更新
低
8. 字段重命名 CHANGE COLUMN 改字段名,应用层查询可能 404
低
9. 大表 DDL (无 gh-ost) 表大小 > 16MB 但 DDL 没勾 gh-ost,锁表时间可能 5-10 分钟
提示
10. 字符集隐式转换 字段没显式字符集 → 走表默认,SHOW 时显式打出(可能让 RD 误以为 diff 变了)
提示
11. 隐式 DEFAULT 行为 MySQL 8.0.13+ 隐式 DEFAULT (TIMESTAMP/DATETIME 等),DDL 不写 DEFAULT 也会有

⚠️ DBA 兜底:字段 diff 高风险提醒

工单 #85 的 DDL 检测到 1 项高风险 字段 diff,需要 DBA 人工确认:

⚠ 数据截断风险

do_black_reson VARCHAR(255) → VARCHAR(128)

已有 241558 行数据,如果 do_black_reson 字段值超过 128 字符会被截断。
建议操作: 让业务 RD 先跑 SELECT COUNT(*), MAX(LENGTH(do_black_reson)) FROM accesscard_black_detail 确认无数据风险。

入口 1:SQL 检测结果页

入口 2:工单详情页 modal

DBA 在工单详情页审批时,点 "字段 diff" 按钮弹窗(8/24 修法,modal HTML 元素位置错修了)。

主要面向 DBA 兜底,显示 diff + 11 风险 + 高风险弹窗确认。

URL: /detail/<workflow_id>/ (DBA 审批)

与 gh-ost 联动(v0.3.0 整合亮点)

字段 diff 检测 + gh-ost 是同一个 sql/extensions/ddl_gh_ost/ app 下的功能,可以联动:

  • 大表 + 高风险: 字段 diff 命中"大表 DDL"风险时,自动建议勾 gh-ost
  • DBA 兜底对话: 高风险时弹"建议用 gh-ost,业务 0 中断"提示
  • 审批流联动: 8/24 修法后,字段 diff modal 跟 gh-ost 进度面板在同一页面可切换

8 维对比实现 (services/column_diff.py 简化版)

def compare_column(old_col: dict, new_col: dict) -> list:
    """8 维字段对比, 返回 [{'dim': ..., 'old': ..., 'new': ..., 'changed': bool}, ...]"""
    diff = []
    for dim, (old_val, new_val) in [
        ('数据类型', (old_col['data_type'], new_col['data_type'])),
        ('长度',    (old_col['character_maximum_length'], new_col['character_maximum_length'])),
        ('字符集',  (old_col['character_set_name'], new_col['character_set_name'])),
        ('排序规则', (old_col['collation_name'], new_col['collation_name'])),
        ('可空性',  (old_col['is_nullable'], new_col['is_nullable'])),
        ('默认值',  (old_col['column_default'], new_col['column_default'])),
        ('注释',    (old_col['column_comment'], new_col['column_comment'])),
        ('索引关联', (old_col['indexed'], new_col['indexed'])),
    ]:
        diff.append({
            'dim': dim,
            'old': old_val,
            'new': new_val,
            'changed': old_val != new_val,
        })
    return diff

def check_risks(diff: list, old_col: dict, new_col: dict) -> list:
    """11 条风险规则检查"""
    risks = []
    # 1. 数据截断
    if is_length_shrink(old_col, new_col):

    if is_type_shrink(old_col, new_col):
        risks.append({'level': 'high', 'rule': '类型转换风险', ...})
    # ... 11 条规则
    return risks
