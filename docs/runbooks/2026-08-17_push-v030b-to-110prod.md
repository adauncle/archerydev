**如果 HUP 失败**: 杀进程手动起
```bash
pkill -f gunicorn

chown -R archery:archery /dbdata/archery_v114_c9236a0

# 3. 还原 DB 到 7 日前
gunzip -c /backup/upgrade_v114/archery_pre_v114_20260729_191628.sql.gz | \
  mysql --socket=/tmp/mysql_3306.sock -uroot -p'xxx' archery

# 4. 还原 SECRET_KEY
cp /backup/upgrade_v114/v110_secret_key.txt /dbdata/archery_v114_c9236a0/.env  # ⚠️ 确认格式
chown archery:archery /dbdata/archery_v114_c9236a0/.env

# 5. 重启 + 验证
```

**回滚耗时**: 30-60min (DB 还原 112MB dump ~5-10min)
**数据风险**: 高 (7 天的所有数据会丢, 业务侧需事先通知)

### 8.4 不回滚 (业务功能回退)

**场景**: 某个 gh-ost 功能不好用但不影响业务
**做法**: 在 admin 后台 disable 该功能, 不动代码不回滚
**例如**:
- v0.4.5 rebuild 觉得不稳, 设 `CUSTOM_GH_OST_REBUILD_ENABLED=False`
- 字段 diff 觉得太烦, 设 `CUSTOM_COLUMN_DIFF_ENABLED=False`
- 任务列表页不想给 RD 看, 改 perm
