# Archery 8.0 兼容改造 roadmap (后一个大版本, 不在 D35)

> **日期**: 2026-09-07 17:40
> **触发**: 110 prod 业务方 SQL 查询截图报错 `无法校验查询语句权限...line 1 column 100 near 'ORDER BY wi.id)'`
> **决策**: 用户拍板放到后一个大版本, D35 不做 (D35 focus on ddl_sync 部署)
> **关联**: 跟 D35 无关, 跟 goinception v1.3.0 (TiDB 1.3.0 解析器) 仓库停更有关

---

## 一、问题

业务方在 110 prod 跑这条 SQL:
```sql
SELECT (SELECT IFNULL(MAX(id), 0) FROM waybill_load) + ROW_NUMBER() OVER (ORDER BY wi.id), ...
FROM waybill_info wi ...
```

报 `无法校验查询语句权限, 错误信息: line 1 column 100 near 'ORDER BY wi.id)'`。

Navicat 跑没事, Archery 平台报语法错。

## 二、根因

`sql/query_privileges.py:493` `_table_ref()` 函数调用 `GoInceptionEngine.query_print()` 解析 SELECT 语法树（用于权限校验 + 列脱敏）。goinception 底层用 **TiDB 1.3.0 解析器**, **不支持 MySQL 8.0 窗口函数** (`ROW_NUMBER() OVER (...)`, `LAG()`, `LEAD()`, `RANK()`, `DENSE_RANK()` 等)。

`hanchuanchuan/goinception` 仓库 **2022-06-12 后停更**（v1.3.0 是最后一个 release, 作者没出 v1.4.0）。Docker Hub `latest` tag 跟 v1.3.0 digest 一样 (`b3c0dd26fb50`), 升级 `latest` 实际 = 当前 1.3.0, 解决不了问题。

## 三、用户拍板 (9/7 17:40)

走 D 方案 (业务方继续用 Navicat), **A 方案改造放后一个大版本**。

## 四、未来改造方案 (待大版本启动时做)

### A 方案: 改 `sql/query_privileges.py:493` 走 MySQL 原生 EXPLAIN

**思路**: SELECT 查询权限校验绕开 goinception 解析器, 走 MySQL 原生 EXPLAIN (MySQL 服务端解析, 完整支持 8.0 语法)。

```python
# 修前
engine = GoInceptionEngine()
query_tree = engine.query_print(instance=instance, db_name=db_name, sql=sql_content)
return engine.get_table_ref(json.loads(query_tree), db_name=db_name)

# 修后 (对纯 SELECT 走 EXPLAIN, 其他 SQL 保留 goinception 路径)
import pymysql
conn = pymysql.connect(host=..., port=..., user=..., password=..., db=db_name)
cur = conn.cursor()
cur.execute(f"EXPLAIN {sql_content}")
table_refs = [row[2] for row in cur.fetchall() if row[2]]
return list(set(table_refs))
```

**优点**:
- 业务方 Archery SQL 查询支持所有 MySQL 8.0 语法 (窗口函数 / CTE / 递归等)
- 不依赖 goinception 解析器, goinception 只管 DDL/DML 审核
- Archery 平台不受 goinception 仓库停更影响

**风险**:
- EXPLAIN 对纯 SELECT 有效, DML/INSERT/UPDATE/DELETE 不走 EXPLAIN
- 需要对纯 SELECT 走 EXPLAIN, 其他 SQL 走原 goinception 路径
- EXPLAIN 返回的 table 字段格式跟 query_print 不同, `_db_priv` 调用逻辑可能需要适配

**预估工作量**:
- 代码改动: ~50 行
- 134 dev 演练: 30 分钟
- 推 110 prod: 30 分钟
- 总: 半天

## 五、短期 workaround (D35-D37 期间)

业务方跑含 MySQL 8.0 语法的 SQL (ROW_NUMBER OVER, CTE 等):
1. **首选**: Navicat / DataGrip / DBeaver 等原生客户端直连
2. **Archery 临时用法**: SQL 拆成两步 - 先 explain 拿到涉及表名, 再用 Archery 跑不带窗口函数的版本
