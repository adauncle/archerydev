根因: 业务方实战 SQL 是 `add index idx_owner_name(owner_name)` —— **name 后直接是 `(`,
     没空格!** 但原 _RE_INDEX_ADD regex 假设 `\s+` (一个或多个空格) 才能匹配.

原 regex:
```python
_RE_INDEX_ADD = re.compile(
    r"^\s*ADD\s+(?P<unique>UNIQUE\s+|FULLTEXT\s+|SPATIAL\s+)?"
    r"(?:INDEX|KEY)\s+"
    r"(?:`?(?P<index_name>[^`\s(]+)`?\s+)?"  # ← 这里 \s+ 必须有空格
    r"\((?P<columns>[^)]+)\)",
    re.IGNORECASE,
)
```

修法: `\s+` 改成 `\s*` (name 后允许 0 个空格).

修后:
```python
r"`?(?P<index_name>[^`\s(]+)`?\s*"  # ← 业务方实战: name 后无空格 (idx_owner_name(owner_name))
```

演练脚本 _w3_index_drill.py 加 Case G (业务方实战真实无空格):
  ADD INDEX idx_owner_name(create_time) name 后无空格 → high reject ✅ PASS

## 9/16 修法实战教训 (跨项目可复用)

跨项目写 SQL 解析 regex, **必考虑"实战 SQL 形态"**, 别只考虑"典型 SQL 形态":
- 典型: `ADD INDEX idx_name (col)` (name 后有空格)
- 实战: `ADD INDEX idx_name(col)` (name 后没空格, 业务方实战)
- 实战: `ADD INDEX `idx_name` (col)` (name 带反引号)
- 实战: `ADD INDEX idx_name( col)` (name 后空格在 `(` 后)
- 实战: `ADD INDEX idx_name ( col)` (name 后空格 + 列名前空格)

修法: regex 用 `\s*` 而不是 `\s+` (允许 0 空格), 边界 case 演练必覆盖业务方真实 SQL.
